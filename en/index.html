RTT TRANSLATOR

Translate a file without losing its structure.

RTT inspects the file and the active route first: Web and Windows extract PDF text layers, Android can OCR scanned pages on device, SRT/VTT timing stays intact, and Office files are uploaded only when the selected service declares native document translation support.

PDF and scans

Web and Windows extract text layers; Android can OCR pages. Empty scans get an explicit OCR or native-document route message.

Office and layout

Native APIs such as DeepL use upload, status polling, and result download. Text-only models are never presented as layout-preserving.

Subtitles and structured files

SRT and VTT keep indexes and timing. TXT, Markdown, HTML, JSON, XML, and XLIFF are also accepted.

Video to subtitles

Extract audio locally and export SRT, VTT, ASS, or TXT with translated-only or bilingual cues. Cloud ASR receives audio only after consent; frames are never uploaded.

Your content stays on your device by default

RTT collects no telemetry. Diagnostics are off by default and never record audio, caption text, or API keys. Local mode uploads nothing; cloud mode identifies the active capability, model, and provider.

Know before you start

  • DRM media, apps that prohibit AudioPlaybackCapture, and FLAG_SECURE screens cannot be bypassed.
  • Protected Android call audio cannot be captured directly. For voice chat, use a microphone with speakerphone.
  • Chinese voice output is delayed translated speech, not a lip-synced film dubbing track.
  • Larger models are usually more accurate but need more storage, memory, and power.
